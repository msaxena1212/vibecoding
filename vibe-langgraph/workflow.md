# Vibe-LangGraph Development Workflow

This document outlines the end-to-end process of how the **Vibe-LangGraph** platform handles user requests, orchestrates agents, and manages state.

---

## 1. System Architecture
The platform is built on a **Modular Agentic Loop** using FastAPI for the backend and LangGraph for agent orchestration.

### Key Components:
- **FastAPI Backend**: Handles API routing, database persistence, and static file serving.
- **LangGraph State Machine**: Orchestrates the flow between different LLM-powered agents.
- **SQLite Database**: Stores project snapshots, codebase states, and conversational history.
- **Single-Page UI**: A premium, Tailwind-powered dashboard for real-time visualization.

---

## 2. The Agentic Pipeline
When a user submits a prompt (e.g., "Build a dashboard"), the following sequence is triggered:

### Phase A: Planning (The Architect)
- **Agent**: `run_planner`
- **Output**: A structured JSON plan following a 7-step PRD process.
- **Goal**: Define the folder structure, technical requirements, and aesthetic guidelines (Apple-style).

### Phase B: Generation (The Builder)
- **Agent**: `run_generator`
- **Logic**: Iterates through the files defined in the plan.
- **Standards**: Uses CDN-based dependencies (Tailwind, Babel, Chart.js) to ensure **Instant Visibility**.

### Phase C: Linking (The Optimizer)
- **Agent**: `run_linker`
- **Logic**: Analyzes the generated code to build a dependency graph and ensure all imports are wired correctly.

### Phase D: Validation & Sanitization
- **Agent**: `run_validator` (Checks for consistency).
- **Final step**: The codebase state is sanitized and saved to the database.

---

## 3. Data Flow & Persistence
1.  **Request Entry**: User sends a POST request with an `intent` and optional `project_id`.
2.  **Initial Snapshot**: A project "shell" is created in the database immediately to ensure durability.
3.  **Conversation Tracking**: User messages and AI responses are associated with a unique `session_id` (the Project ID).
4.  **State Loading**: For follow-up requests, the entire previous state (code + messages) is injected into the prompt context.

---

## 4. Operational Guidelines

### How to Start a New Build
1. Click **"New Chat"** in the sidebar to reset the session context.
2. Enter your prompt in the textarea.
3. Monitor the **Status Loader** (Planner -> Generator -> Linker).

### Managing Generated Code
- **Explorer**: Navigate the folder structure generated by the AI.
- **Preview**: View the live-rendered UI immediately (powered by CDN transpilation).
- **Codebase**: Inspect and copy raw source code.
- **Graph State**: View the underlying JSON state of the LangGraph machine.

---

## 5. Future-Ready Design
- **Incremental Updates**: The platform is designed to apply partial updates to specific files without rewriting the entire codebase.
- **Framework Agnostic**: While optimized for React/Tailwind (CDN), the structure supports Next.js and Expo expansion.
- **Traceability**: All LLM interactions are logged in `generation_log` for auditing and debugging.
